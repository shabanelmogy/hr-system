## RISK-013 — Mobile Expo CLI transitive Zod advisory

- **Surface / owner / status:** Mobile; Mobile Architecture + Security; Open, recorded 2026-10-27.
- **Source and context:** During `FOLLOW-008` SDK57 patch alignment, an audit of the previous HEAD lockfile reported ten affected package entries (nine high, one critical). After SDK patches and compatible security updates, the full and production lockfile audits each report three high entries and zero critical: `zod`, `@expo/cli`, and `expo`. These are npm package-entry counts, including ancestor propagation, rather than three independent vulnerabilities or proven exploitable application journeys.
- **Verified dependency path:** `expo@57.0.31 -> @expo/cli@57.0.32 -> zod@3.25.76`. The [official SDK57 CLI source](https://github.com/expo/expo/blob/sdk-57/packages/%40expo/cli/package.json) and npm SDK57 version metadata still declare `^3.25.76`. The current [Zod advisory](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5) identifies versions below 4.6.6 and memory exhaustion during oversized collection validation. The client application's own Zod is upgraded to 4.6.7.
- **Completed mitigation:** Axios 1.21.0, application Zod 4.6.7, follow-redirects 1.16.2, shell-quote 1.12.0 and brace-expansion 1.1.21/5.0.12 replace affected compatible versions. SDK57 patch alignment also updates affected code-signing/source-map dependency paths. The local decoder override is preserved. Expo's xcode 4 dependency uses Node crypto rather than uuid; the obsolete uuid override is retired and its compatibility gate now exercises PBX identifier generation through xcode's CommonJS API.
- **Impact and present boundary:** The moderate production dependency-audit gate fails. Expo's CLI is included by npm in the production dependency tree. The 2026-10-28 Android source-map inspection covers 3,030 unique sources and excludes CLI tooling schemas and legacy Zod; its one CLI-owned module is Expo's intentional Metro loader. This is artifact-specific exposure evidence, not an upstream fix, signed-device result or security acceptance.
- **Reason it is not resolved in this change:** No patched Zod 3 version is offered within the latest SDK57 CLI dependency range. npm's suggested forced change downgrades Expo to 54.0.38; replacing the CLI's declared Zod 3 with Zod 4 would cross its supported major contract. Neither change belongs to this bounded SDK57 patch correction.
- **Exact reopening trigger / target milestone:** Reassess before the next external preview or release candidate, whenever Expo ships a compatible SDK57 CLI fix, or before a separately planned SDK migration. Verify the fixed dependency path with clean install, both audits, Doctor, full Mobile check, native-config prebuild and Android export. Do not suppress or lower the audit gate.
- **Canonical sources:** `documentation/guides/mobile/MOBILE_API_READINESS_REVIEW.md`, `documentation/guides/mobile/MOBILE_RELEASE_RUNBOOK.md`, `mobile-react/package.json`, and `mobile-react/package-lock.json`. Device/signing acceptance remains separately owned by `PROD-026` and the existing release notes.
- **Recheck on 2026-10-28:** npm metadata still reports SDK57 CLI 57.0.32 and latest CLI 58.1.16 with `zod: ^3.25.76`; a general SDK upgrade does not currently offer this fix. The installed CLI's direct Zod callers are `DevToolsPlugin.schema` and `createMCPDevToolsExtensionSchema`, serving development plugin/MCP metadata; plugin command/output collections are not size-bounded in the upstream schema. The [upstream SDK57 schema](https://github.com/expo/expo/blob/sdk-57/packages/%40expo/cli/src/start/server/DevToolsPlugin.schema.ts) and [Zod v4 size-check fix](https://github.com/colinhacks/zod/pull/6652) inform this assessment. The new Android map gate rejects these tooling modules and legacy Zod paths while allowing only the [documented Metro loader](https://github.com/expo/expo/blob/sdk-57/packages/%40expo/cli/metro-require/require.ts). `RISK-014` owns the newly reported Low advisory; the three High entries for this path remain unresolved.
