# ERP Platform Template — Decisions

Approved decisions for this plan. Cross-plan open decisions live in
`documentation/plans/notes/DECISION_BACKLOG.md` (DEC-011 … DEC-016).

| ID | Decision | Status | Selected direction | Reason | Affected surfaces |
| --- | --- | --- | --- | --- | --- |
| D-001 | Platform base | Approved (owner, 2026-09-28) | This ERP repository is the base for API, Web, and Mobile. The School application becomes the `education-module` plan; its Clean Architecture API and Next.js UI are not imported. | ERP is ahead on modularity, tenancy, security, clients, and planning (E-001 … E-013). | All |
| D-002 | Web UI library | Approved (owner) | MUI stays the web component library. The earlier shadcn/ui direction from the School work is withdrawn. | Existing shared components, governance, and screens are MUI (E-007, E-010). | Web |
| D-003 | Mobile UI approach | Approved (owner) | React Native native components without a third-party UI kit, styled from shared tokens. | Matches the current mobile client (E-009, E-011). | Mobile |
| D-004 | Design tokens | Approved (owner) | `packages/tokens` (`@app/tokens`) is the single source of colors, typography, spacing, radius, elevation, motion, layout. Web consumes it through `createMuiThemeOptions`; mobile through `getTheme`. | One visual language on both clients; the palettes already came from the mobile app (E-029, E-032). | Web, Mobile |
| D-005 | Single-customer deployments | Approved (owner) | A single customer is one tenant; when a user has exactly one eligible tenant and company, login completes without a selection step. | The login contract already returns `authenticated` when no selection is needed (E-004, E-035). S0 verifies it end to end. | API, Web, Mobile |
| D-006 | Planning authority | Superseded by D-013 | `documentation/plans/` is canonical in this repository. `templates/planning/` is the portable kit for products outside it; `ERP_MAPPING.md` maps skills to P0–P9 and G0–G4. | Avoid two competing planning systems (E-012, E-031). | Documentation |
| D-007 | What moves from the School repository | Amended by D-013 | Import `templates/planning/` and `packages/tokens/`, plus the School review documents as evidence under `imported/`. Do not import the School generators or content profiles. | Generators target a different architecture (E-031). | Repository |
| D-008 | Product and namespace name | Approved (owner: folder + remnants) | Repository folder becomes `erp-system` (owner renames it). Code namespace stays `ErpSystem`. Remaining `HrManagementSystem` names are removed in S0, except JWT issuer/audience, which follow DEC-012. The HR module keeps its name. | The code is already `ErpSystem` (E-001, E-014, E-017). | Repository, API |
| D-009 | MUI breakpoints | Approved | `createMuiThemeOptions` keeps MUI default breakpoints unless called with `useTokenBreakpoints: true`. | Changing breakpoints silently would shift existing layouts (E-036). | Web |
| D-010 | MUI `secondary` mapping | Approved | MUI `palette.secondary` = token `brand2`; quiet surfaces and extra brand colors are exposed under `palette.app`. | MUI treats secondary as a strong color; the token `secondary` is a quiet surface. | Web |
| D-011 | New screen patterns | Approved | Patterns proposed from the School blueprint enter `SCREEN_PATTERN_CATALOG.md` as `Candidate` with IDs P-008 … P-014 and become `Active` only when a module ships a source reference, per the catalog protocol. | Catalog rule (E-030). | Web, Mobile, Documentation |
| D-012 | Review deliverable | Approved (owner) | This plan records the review and merge plan only; no runtime code changes are part of the planning step. The tokens package and planning kit are non-runtime assets and were imported. | Owner choice, 2026-09-28. | All |
| D-013 | Retire the imported planning kit | Proposed (review 2026-09-28) | `documentation/plans` + `documentation/system` + `.codex/skills` are the template's planning and delivery system. Carry over only two missing capabilities as skills (`erp-business-planning`, `erp-legacy-migration`), then delete `templates/planning/`. `templates/` keeps only the S5 generator. | The kit duplicates every ERP step except external-application migration (`DOCUMENTATION_AND_TEMPLATE_REVIEW.md` §3). | Documentation, AI skills |
| D-014 | Minimal documentation set | Proposed (review 2026-09-28) | Adopt `DOCUMENTATION_AND_TEMPLATE_REVIEW.md` §6: a file exists only with an owner and an inbound link; module packages start with four files; sub-READMEs are created when they have content. | Removes ~130 placeholder, duplicate, or archived files without losing knowledge. | Documentation, `New-ErpModule.ps1` |
