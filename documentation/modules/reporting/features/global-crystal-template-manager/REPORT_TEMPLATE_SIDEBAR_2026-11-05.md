# تنزيل ورفع قالب التقرير من القائمة الجانبية — 2026-11-05

## 1. طلب المستخدم والعقد

طلب المستخدم إتاحة تحميل التقرير وإعادة رفعه من القائمة الجانبية أثناء عرضه. المقصود في هذا التنفيذ هو قالب RPT؛ تنزيل PDF وفتحه يحتفظان بإجراءاتهما الحالية. هذا مدخل إضافي لدورة الإصدارات الموجودة في GCT-1، دون API أو صلاحيات أو نشر تلقائي جديد.

## 2. تركيب التنفيذ

GlobalReportView يعرض تنزيل المصدر باستخدام GlobalReportState الحالي عندما يسمح canDownloadSource القادم من الخادم. ويعرض رفع إصدار للمستخدم الذي تسمح له سياسة الإدارة الحالية بـView وUpload وEdit للكيان. لا تظهر إدارة القالب لمجرد امتلاك صلاحية عرض PDF أو تنزيل المصدر.

عند طلب الرفع فقط، يُحمّل GlobalReportTemplateEditor مؤجلًا. هذه مساحة تحرير مستقلة توفر GlobalTemplateState وGlobalTemplateAccessState مرة واحدة، وتعيد استعمال GlobalTemplateUploadDialog وGlobalTemplateDetailDialog مع تبويب Versions. لا تُحمّل خدمات الإدارة أو بياناتها لمستهلك التقارير العادي عند بدء الصفحة.

GlobalTemplateState يحل هوية الإدارة من استعلام موجود بفلتر reportKey يساوي المفتاح المحدد والكيان والحالة المنشورة. يشترط نتيجة واحدة ثم يجلب تفاصيلها عبر المسار الموجود، ويتحقق من هوية التقرير العام ورمز الإصدار الحالي وصلاحية Upload الخاصة بالتقرير قبل فتح الرفع. لا يعامل ID الكتالوج العام ذي 64hex على أنه GUID الإدارة ولا يختار أول تقرير مشابه.

عقد الخادم الحالي في `GlobalCrystalReportIdentity.cs` يعرّف SourceId بأنه SHA256 للنص `managed-global` ثم newline ثم GUID التقرير بصيغة N. أما rowVersion الخاص بالعارض فهو Token من GUID الإصدار بصيغة N وfingerprint العقد الحالي وSHA256 الملف، مفصولة بـnewline؛ ليس بصمة الملف الخام. المساعدة `global-template-viewer-identity.ts` تطابق الاثنين باستخدام [Web Crypto digest](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/digest) في HTTPS، دون اعتماديات أو endpoint جديد. بعد تحميل ACL، يُعاد التحقق من RowVersion الإدارة وهوية الإصدار المنشور وبصمة العقد حتى لا يُقبل snapshot متقادم. هذا فحص اتساق للواجهة، والخادم يبقى صاحب سلطة الصلاحيات.

## 3. السلوك والحدود

الرفع يضيف إصدارًا غير منشور إلى نفس GUID؛ تبقى النسخة المنشورة الحالية حتى تنفيذ Publish الصريح من نافذة الإصدارات. يستخدم المستخدم نفس اختيار الملف والتحقق وأخطاء الحقول والتركيز وحماية الإغلاق الموجودة. إغلاق تفاصيل القالب يعيد تحميل كتالوج العارض لالتقاط أي نشر صريح حدث.

تغيير التقرير أو الكيان أو هوية الجلسة يدمر مساحة التحرير ويُلغي طلباتها. فشل الحل أو تغير hash يعرض خطأ تعارض، وفقد Upload في ACL يمنع الرفع. لا تغييرات بيانات أو schema أو migration في هذه الصيانة؛ API وNext.js وMobile تحتفظ بعقودها الحالية، وإدارة القوالب في Mobile مستبعدة أصلًا.

## 4. التحقق

نجح `npm run check` كاملًا: 98 ملفًا و567 اختبارًا، 30 اختبار architecture مع فحص المصادر، lint، الأنواع والقوالب والتنسيق وproduction build. بقي initial عند 574.45kB وتحذير 500kB الموروث RISK-020 دون تغيير الميزانية. تشمل الاختبارات حل المفتاح بدقة، hash المتقادم، صلاحية الإدارة، Upload في ACL، إعادة استخدام نافذتي الرفع والإصدارات وعدم النشر التلقائي.

نجحت 12 حالة Chrome فوق production build: ثماني EN/AR × light/dark × 390/1440 للتحميل والرفع إلى نفس GUID والإبقاء على النشر الصريح، وحالة قارئ لا يرى Upload ولا يرسل طلبات إدارة، وحالة رفض ACL وحالة Token متقادم وحالة اختلاف SourceId رغم تطابق المفتاح والملف. فحص التقارير العام المركّز نجح في ثماني حالات lifecycle بعد تحديث selectors لتبويب الخيارات؛ FOLLOW-026 أصبح Verified. لا توجد pageerrors أو overflow في الحالات المنفذة. جرى فحص صورة الإصدارات العربية الداكنة عند390px بصريًا.

تستخدم الاختبارات اعتراض جميع طلبات API وكتابات الملفات الوهمية؛ لا تمنح قبول Crystal أو API مستضافًا أو جهازًا فعليًا جديدًا. السكربت الجديد يقرأ production bundle عبر Playwright دون تشغيل سيرفر. تم إيقاف سيرفر4220 المؤقت المستخدم لاختبار lifecycle بعد انتهاء التحقق.

الأوامر القابلة للإعادة من web-angular هي `node scripts/verify-report-template-sidebar-browser.mjs` بعد build، و`node scripts/verify-reporting-browser.mjs --focused` مع سيرفر تطوير اختباري على4220.
