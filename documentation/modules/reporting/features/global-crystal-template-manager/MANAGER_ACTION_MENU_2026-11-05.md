# قائمة إجراءات مدير التقارير — 2026-11-05

## 1. الطلب والعقد

طلب المستخدم تجميع أزرار Global Report Manager في Dropdown ووضع عناصر الشريط في صف واحد. النطاق صيانة عرض الإجراءات الموجودة في GCT-1. يجمع زر «العمليات» (Actions) رفع RPT، تسجيل التقارير الموجودة، فتح المصمم وتنزيل المخطط. تظل صلاحيات Create وDownload وحالة الانتظار واختيار الكيان مملوكة للحالة الحالية. يظل تحديث الصفحة في رأسها، ومجموعة تنزيلات Overview في مكانها.

## 2. الملكية وإعادة الاستخدام

أضيف `ActionMenuButton` إلى Shared لعدم وجود قائمة إجراءات مرتبطة بزر: `ActionButtonGroup` يجمع أزرارًا، و`ContextMenuPanel` مخصص لقائمة السياق. المكوّن الجديد يعيد استخدام `ActionButton` ويكيّف PrimeNG Menu مع أيقونات التطبيق وHTML/SCSS خارجيين. يستقبل قائمة `ActionMenuItem` بمعرفات فريدة ونصوص مترجمة وdisabled، ويرسل المعرف فقط. لا يعرف صلاحيات التقارير أو خدماتها. يمنع تنفيذ callbacks قديمة لعناصر حُذفت أو عُطلت، ويغلق عند تعطيله. تكرار المعرفات يعطل القائمة.

يُنشئ `GlobalTemplateList` العناصر المسموحة ويعيد فحص صلاحية العنصر وحالة الانتظار قبل توجيهه إلى الحالة أو المصمم الحالي. الرفع والتسجيل والتصميم لا تنشئ مسار تنفيذ آخر. يبقى تنزيل المخطط معطلًا عند اختيار كل الكيانات أو غياب Download للكيان المحدد.

## 3. التخطيط والوصول

متابعة المستخدم في الجلسة نفسها أكدت أن السهم السابق غير واضح كدلالة Dropdown. أصبح المؤشر `chevronDown` بعد النص مع فاصل منطقي خفيف، ويدور عند فتح القائمة. أضيف إلى ActionButton موضع إسقاط اختياري `buttonEndIcon`، وفق ترتيب المحتوى الموثق في [PrimeNG Button](https://primeng.dev/button#icons)، دون تغيير الأزرار التي لا تستخدمه. يظل الزر هدفًا تفاعليًا واحدًا كاملًا، وتنعكس الجهة مع RTL مع احترام reduced-motion. أضيف اختبار لموضع المؤشر بعد النص وفحص متصفح لجهته وفاصله وحالة الفتح.

يستهلك الجدول `toolbarLayout="single-row"` الموجودة. يضع البحث وفلترَي الكيان والحالة والإجراءات وخيارات الجدول في الصف نفسه. الشاشات الضيقة تمرر الشريط أفقيًا داخل مساحته. يملك `CollectionFrame` الحد الأدنى 220px للبحث النصي فقط؛ بحث الحقل/المعامل يحتفظ بـ540px. لا تنسيق خاص بالميزة أو تغيير الافتراضي لبقية الجداول.

تُعرض القائمة خارج مساحة التمرير عبر popup وappendTo=body. يملك PrimeNG الأسهم وEscape وإعادة التركيز. يتبع الزر عقد ActionButton الحالي: type=button واسم مترجم وaria-haspopup/menu وaria-controls وaria-expanded. تمت مراجعة API ومثال popup عبر PrimeNG MCP، ونجح validate_usage دون ملاحظات؛ المرجع [PrimeNG Menu](https://primeng.dev/menu). قبول نسخة22.1.4 الفعلية يعتمد أيضًا على المتصفح.

يعتمد ثيم المشروع تحميل إعدادات المكونات المتبناة فقط. لذلك يحمّل المكوّن المشترك Aura Menu عبر `dt`، ويصل خلفيته وحدوده وألوانه ومسافات عناصره بمتغيرات الثيم الحالية، وفق نمط ContextMenuPanel القائم. يوصي دليل [Scoped Tokens](https://primeng.dev/theming/styled#scopedtokens) بهذه الواجهة لتخصيص المكوّن. كشف الفحص البصري الأول غياب خلفية القائمة والمسافات رغم نجاح التفاعل؛ أضيف فحص متصفح للخلفية والحد والظل وpadding، وأثبت فشله قبل ربط الرموز. لا تغيير للـpreset العام ولا CSS خاص بمدير التقارير.

## 4. التحقق وحدوده

تسجل [نتيجة التحقق الحالية](verification/MANAGER_ACTION_MENU_2026-11-05.json) أوامر الفحص ونتائجها وبصمات المصادر. يغطي فحص المتصفح production build باستخدام API fixtures، ولا يشغّل خادمًا أو يكتب تقريرًا حقيقيًا. تبقى أدلة sidebar والإصدارات السابقة بسياقها وتاريخها؛ لا يُعاد تفسيرها على أنها فحص هذا التعديل.

أظهر الفحص الشامل الأول سباقًا في اختبار sidebar السابق: استُخدم `whenStable()` قبل انتظار نتيجة `crypto.subtle.digest` القادمة عبر Promise/RxJS، فسبق التحقق وصول تفاصيل القالب. أصبحت اختبارات المطابقة تنتظر الحالة النهائية صراحةً بـ`expect.poll` قبل فحص العرض. لم يُغيَّر مسار التحقق أو الصلاحيات في التطبيق لمعالجة هذا الاختبار.

تُعاد الحالات من `web-angular` بالأمر `node scripts/verify-manager-pagination-browser.mjs --details --filters` بعد build. يحتفظ مجلد [دليل التنفيذ](verification/manager-action-menu/) بالنتيجة التفصيلية وسجلات الفحص وصورتين ممثلتين؛ تُستخدم ملفات نصية قابلة للحفظ في Git للسجلات الجديدة بدل مسارات log متجاهلة. إعادة التوليد وفحص الوثائق والتخطيط مسجلان في نتيجة التحقق الحالية.
