## 2. دومين البيانات الجغرافية والأساسية (Geographical Information)

### ✅ ما تم إنجازه بنجاح (Completed & Verified)
- [x] **الدول (`Country`):** كتالوج عام للمنصة يديره الـ `super_admin` مع دعم رموز ISO ورموز الاتصال واللغتين.
- [x] **المحافظات / الولايات (`State`):** ربط صارم مع الدولة، كود معرف، ودعم كامل للغات.
- [x] **المراكز / الأحياء (`District`):** مستوى إداري اختياري يتبع المحافظة.
- [x] **أنواع العناوين (`AddressType`):** تصنيف استخدام العناوين على مستوى الشركة.
- [x] **النطاق الجغرافي للشركة (`CompanyCountry`):** قصر إدخال العناوين على الدول المصرح للشركة بالعمل فيها.
- [x] **دولة التسجيل القانوني (`Company.RegistrationCountryId`):** فصل الكيان القانوني عن مواقع العمل.
- [x] **العناوين المشتركة (`Address`):** جدول عنوان مجرد وقابل لإعادة الاستخدام.
- [x] **جداول الربط الغرضية:** `CompanyAddress` (للمقر المسجل، الفواتير، المراسلات) و `BranchAddress` (لمواقع العمل).
- [x] **الشاشات والمزامنة:** شاشات الويب (`web-next`) والموبايل (`mobile-react`) والـ API متطابقة وتستخدم نفس المكونات المشتركة (`MyDataGrid`, `CardViewPagination`, `MyForm`).
- [x] **معالجة أخطاء المصادقة اللحظية:** إصلاح استدعاءات SignalR 401 و Notifications 403 لمستخدم الـ `super_admin`.

### ⏳ الملاحظات والتحسينات المستقبلية المجدولة (Deferred & Planned)
- [ ] **بصمة الحضور الجغرافية (`GeofenceRadiusMeters`):**
  * *الوصف:* إضافة حقل نصف القطر بالمتر في `BranchAddress`.
  * *شرط التفعيل (Trigger):* عند البدء في موديول تسجيل الحضور عبر الهاتف المحمول (Mobile Attendance).
- [ ] **عناوين الموظفين (`EmployeeAddress`):**
  * *الوصف:* جدول وسيط يربط الموظف بعناوينه (محل الإقامة الحالي، العنوان بالبطاقة/الهوية، عنوان الطوارئ) مع حماية خصوصية البيانات (PII).
  * *شرط التفعيل (Trigger):* عند بناء ملف الموظف الشامل في دومين `Employees`.
- [ ] **تنسيق العناوين ديناميكياً بحسب الدولة (Country Address Format):**
  * *الوصف:* جعل الحقول الإلزامية في العنوان تتغير حسب الدولة (مثل اشتراط الرمز البريدي في أمريكا، والحي في مصر).
  * *شرط التفعيل (Trigger):* تحسينات مرحلة التوسع الدولي.

## 3. دومين الهيكل التنظيمي (Organizational Structure)

### ✅ ما تم إنجازه بنجاح (Completed & Verified)
- [x] **الفصل الرباعي للوظائف (The 4-Tier Job Architecture):**
  * المسمى الوظيفي (`JobTitle`) مفصول عن الدرجة وسلالم الرواتب (`JobLevel`).
  * المنصب وتخطيط القوى العاملة (`Position.TargetHeadcount`) يربط المسمى والدرجة والقسم.
  * بطاقة الوصف الوظيفي المعتمدة (`JobDescription`) تتبع المنصب بإصدارات (`Version`).
- [x] **الفروع (`Branch`):** وحدة إدارية وتشغيلية متكاملة (مدير، منطقة زمنية، تاريخ افتتاح وإغلاق، مقر رئيسي).
- [x] **الأقسام والإدارات الهرمية:** دعم التسلسل الهرمي الذاتي (`ParentDepartmentId`) لمنع التكرار ودعم مراكز التكلفة.
- [x] **إدارة التوقيتات (`TimeZoneId`):** معتمدة كـ `string (IANA ID)` مع فحص الصلاحية بـ `.NET TimeZoneInfo` لمنع كسر النظام عند التغيرات السياسية للتوقيت الصيفي.
- [x] **الشاشات والتكامل:** 7 شاشات كاملة في الويب والموبايل مع دعم كامل للتقارير والرسوم البيانية والاستيراد (Excel Import).

### 🚀 التحسينات المعمارية المعتمدة للترقية (Approved Enterprise Upgrades)
- [x] **1. دعم الشركات القابضة والتابعة (`ParentCompanyId`):**
  * *الوصف:* إضافة علاقة هرمية ذاتية في كيان `Company` لتمكين دعم مجموعات الشركات الكبرى (Holding & Subsidiaries) والتقارير المجمعة على مستوى المجموعة.
- [x] **2. الإدارات المركزية على مستوى الشركة (Centralized Departments):**
  * *الوصف:* جعل تبعية الإدارة للشركة مباشرة وفك ارتباطها الإجباري بالفرع (`BranchId` يصبح Nullable).
  * *الفائدة:* إمكانية إنشاء إدارات موحدة (مثل المالية والموارد البشرية) تخدم جميع فروع الشركة دون تكرار.
- [x] **3. القوائم المتداخلة للوصف الوظيفي (Job Description Nested Lists via EF Core JSON):**
  * *الوصف:* تحويل نصوص الوصف الوظيفي المسطحة إلى مصفوفات JSON مهيكلة:
    * `DutySections`: مجالات العمل وبنودها والوزن النسبي المئوي لكل مجال (KRAs & Weights).
    * `Skills`: المهارات المطلوبة ودرجة الإتقان (مبتدئ / متوسط / محترف) وإلزاميتها.
    * `EducationRequirements`: المؤهلات والشهادات.
  * *الفائدة:* التقييم السنوي الدقيق للموظفين، والفرز الذكي للـ CVs في موديول التوظيف (ATS).
- [x] **4. شجرة التسلسل الإداري للموظفين (Direct Manager / Org Chart):**
  * *الوصف:* إضافة حقل المدير المباشر (`ReportsToPositionId` أو `ReportsToEmployeeId`) في سجل تعيين الموظف (`EmployeeAssignment`).
  * *الفائدة:* رسم شجرة الهيكل التنظيمي للموظفين وسلاسل الموافقات الإدارية بسهولة مثل أودو.

## 4. دومين الموظفين (Employees - موديول المرحلة القادمة)

### 📌 الوضع الحالي وما هو متوفر في الكود
- الكيانات الأساسية موجودة بالفعل في الباك إند:
  * `Employee`: بيانات الهوية الأساسية، الرقم الوظيفي، حالة الموظف (`Draft`, `Active`, `Suspended`, `Terminated`) مع حوكمة دورة الحياة والتأريخ الفعّال.
  * `EmployeeAssignment`: تعيين الموظف في منصب وفرع وإدارة مع تاريخ بداية ونهاية (`EffectiveFrom`/`EffectiveTo`).
  * `EmployeeContract`: نوع العقد، تواريخ البداية والنهاية، والراتب المالي.

### 📋 المطلوب إنجازه لتشغيل موديول الموظفين بالكامل
- [ ] إضافة `EmployeeAddress` (عناوين الموظف وسرية PII).

- [ ] بناء شاشات إدارة الموظفين في الويب (`web-next`) باتباع النموذج المعياري المشترك.
- [ ] بناء شاشات الموظفين في الموبايل (`mobile-react`).
- [ ] دعم استيراد الموظفين من ملفات Excel وتصدير البطاقات التعريفية.

## 5. ميثاق العمل المتبع (Development & Maintenance Rules)

1. **التوثيق المتزامن:** عند إنجاز أي بند من البنود أعلاه، يتم فوراً تحويل علامته إلى `[x]` وتوثيق التغيير في نفس الخطوة.
2. **عدم كسر القديم (Additive Changes):** أي إضافة جديدة على الجداول السابقة تكون عبر هجرات تراكمية متوافقة مع البيانات الحالية.
3. **التوازي الحتمي والتصميم الكامل للشاشات (Full-Stack UI Parity):** لا يتم إغلاق أي ميزة أو إعلان اكتمالها بمجرد تعديل الـ Types أو الـ API؛ بل يشترط إعادة هندسة شاشات الإدخال والعرض (Form & View) في الويب والموبايل لتلائم أي بنية بيانات جديدة (مثل المحررات الديناميكية للقوائم المتداخلة والمفاتيح الصريحة للحالات)، مع اختبارها عبر رحلات المستخدم الخمس (إنشاء، تعديل، استعراض، بطاقات، وبيانات تجريبية).
