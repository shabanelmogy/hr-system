# تقسيم مكونات Angular — التنفيذ المعتمد

اعتمد المستخدم التقسيم في 2026-11-05. النطاق إعادة تنظيم المكونات الحالية وإزالة التكرار مع الحفاظ على السلوك والصلاحيات ودورة حياة النماذج والطلبات.

## العقود

- تبقى مكونات المجال داخل الميزة، والمساعدات العامة داخل Shared.
- تبقى حالة مدير التقارير موفرة مرة واحدة في الصفحة. لا يكرر الأبناء providers للحالة.
- تستهلك الميزات MyDataGrid؛ تبقى تفاصيله المستخرجة داخل Shared دون توسيع واجهته العامة.
- تبقى Signal Forms والـReactive Forms الموجودة عند حدود التوافق كما هي.
- لا اعتماديات جديدة ولا تغييرات API أو قاعدة بيانات ولا commit أو push تلقائي.
- يعمل التنفيذ في checkout الحالي على فرع مستقل للاستفادة من بيئة التحقق الحالية.

## تشخيص التشغيل بعد التقسيم — 2026-11-05

أظهرت جلسة السيرفر القديمة على 4210 خطأ `closeGuard.requestClose()` رغم أن المصدر كان يحتوي على `closeGuard().requestClose()` وأن ملف مدير القوالب موجود عند مسار public API الحالي. تم إثبات اختلاف رسالة Vite المرسلة من السيرفر عن المصدر على القرص. أُعيد تشغيل تلك الجلسة، ثم نجح production build جديد؛ وأظهر Chrome صفحة Login باستجابة 200، دون error overlay أو أخطاء compilation أو pageerror. لا يعتمد هذا التشخيص على افتراض أن كل خطأ مستقبلي سببه cache.

تحذير Node الخاص بـHTTP/2 أُعيد إنتاجه باستخدام `--trace-warnings` على سيرفر تشخيص مؤقت. المصدر المثبت هو Vite8.3.5 عند تعيين `res.statusMessage` في معالج الرد النهائي. المسار التجريبي غير الموجود رجع 404، وصفحة `/` مع `Accept: text/html` رجعت 200 عبر HTTP/2. هذا التحذير وحده لا يثبت فشل التطبيق، ولا يحدد الطلب الأصلي الذي سببه لدى المستخدم. لم يلزم تعديل runtime أو اعتماديات أو إخفاء تحذيرات Node؛ وأُوقف سيرفر التشخيص بعد التحقق. الدليل المتكرر والأمر التشخيصي في [بيئة Angular](../ANGULAR_ENVIRONMENT.md#development-server-diagnostics--2026-11-05).
