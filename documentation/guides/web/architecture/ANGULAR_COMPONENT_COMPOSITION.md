# تركيب مكونات Angular وإعادة استخدامها

مرجع التنفيذ المتكرر للبنية، مع Angular 22 وPrimeNG 22. القرار D37 يكمل D35/D36. النطاق تنظيم المكونات الحالية، مع بقاء قواعد الأعمال وحالة النماذج لدى الميزة.

## 1. اختيار مكان المسؤولية

| المسؤولية | المكان | مثال حالي |
| --- | --- | --- |
| تفاعل أو عرض عام متكرر بين ميزات | Shared، عبر واجهته العامة | `AppearancePreferences` |
| جزء تنفيذي لا يحتاجه مستهلك Shared مباشرة | ملف داخلي بجانب المكوّن العام | `CollectionOptionsDialog`، `createGridPresentationState` |
| تركيب خاص بالمجال، ألوانه أو قراراته | `components/` داخل الميزة | `CountryCardHeader`، `CountryCardContent` |
| تحميل البيانات، الصلاحيات، تنسيق العمليات واسترداد أخطائها | حالة الميزة وخدماتها | `CountryReadState`، `CountryLifecycleState` |
| تحويل/تنسيق نقي يعاد استعماله داخل الميزة | `utils/` داخل الميزة | `country-presentation.ts` |

ابدأ بالبحث في مكتبة Shared ثم الميزة المرجعية. وسّع المكوّن الحالي بقدرة عامة متوافقة إذا كان قريبًا من الحاجة. استخراج مكوّن محلي مسموح لتركيب محتوى المجال، مع استعمال الغلاف والسلوك المشتركين.

## 2. متى نقسم المكوّن؟

قسّمه عندما تظهر مسؤولية مستقلة ذات مدخلات وأحداث واضحة، أو يتكرر نفس التفاعل، أو يجمع الملف عرضًا طويلًا مع تنسيق عمليات مختلف. عدد الأسطر مؤشر للمراجعة فقط؛ لا ننشئ طبقات إضافية لمجرد تقصير الملف.

في التنفيذ الحالي:

- أدوات اللغة والمظهر كانت مكررة في تخطيط الدخول والـShell، فأصبحت مكوّن Shared واحدًا.
- نافذة إعدادات الجدول أصبحت جزءًا داخليًا؛ `CollectionFrame` ما زال يملك فتح النافذة ويعيد تمرير واجهته الحالية.
- حالة ترتيب الأعمدة وعرضها وتثبيتها وعرضها المحفوظ أصبحت factory محلية لكل Grid؛ القياس وDOM والتفاعل مع PrimeNG ما زالت لدى `MyDataGrid`.
- رأس بطاقة الدولة ومحتواها وتفاصيلها وتأكيد الأرشفة بقيت داخل Countries لأن محتواها وصلاحياتها تخص هذا المجال.
- قالب `GlobalReportView` وتنسيقاته في ملفات خارجية؛ لا حاجة لمكوّن جديد إذا كان المطلوب فقط فصل الملفات.

## 3. مدخلات مضبوطة وأحداث واضحة

المكوّن المشترك يستقبل حالة العرض ويصدر طلب التغيير. لا يحقن خدمة مصادقة أو خدمة مجال أو يكتب التخزين أو يستدعي API.

```html
<erp-appearance-preferences
  [language]="locale.language()"
  [mode]="theme.mode()"
  (languageChange)="locale.setLanguage($event)"
  (modeChange)="theme.setMode($event)"
/>
```

اقرأ الإشارة مرة داخل `computed` عند الحاجة لتضييق اتحاد أنواع؛ لا تعتمد على تضييق استدعاء منفصل للإشارة داخل تعبير آخر. للقيم القابلة لأن تكون فارغة استعمل `@if (expression; as value)` واستخدم المتغير داخل الكتلة، وفق [مرجع Angular](https://angular.dev/guide/templates/control-flow).

الحالة المحلية المسموحة هي ما يخص العرض نفسه، مثل بحث أسماء الأعمدة وفتح النافذة. اختيار اللغة والمظهر والفلاتر والصفحة وحالة الإرسال يظل لدى مالكه الحالي.

## 4. الحفاظ على نطاق الحالة

الأجزاء المستخرجة من صفحة Countries تحقن نفس الحالة الموفرة في الصفحة. لا تكرر `providers` في النافذة أو البطاقة؛ وإلا تُنشأ جلسة بيانات أو عملية معلقة منفصلة. احتفظ بفحوص الصلاحيات والسياق وإلغاء الطلبات واسترداد الإرسال في الحالة المالكة.

`createGridPresentationState` يُنشأ داخل سياق حقن المكوّن. آثاره تتبع عمر نسخة Grid. يستقبل Signals للأعمدة والسياق وخيارات العرض، ولا يصبح خدمة root. تغيير هوية السياق أو مفاتيح الأعمدة يعيد العرض. استعادة snapshot تمر عبر `parseGridPresentation` وتُرفض إذا اختلف السياق أو أخفت عمودًا مطلوبًا أو احتوت قيَمًا غير مدعومة. لا تضمّن سجلات أو صلاحيات أو فلاتر خاصة داخل snapshot.

## 5. الإسقاط وحدود CSS

احتفظ بأسماء ومواضع فتحات `ng-content` و`ng-template` القائمة؛ تمرير `gridOptions` عبر `CollectionFrame` يجب أن يصل إلى النافذة الجديدة. لا تستبدل الإسقاط بمحرّك metadata. الإسقاط نفسه لا يؤجل إنشاء المحتوى؛ راجع [توثيق Angular](https://angular.dev/guide/components/content-projection).

انقل تنسيقات الجزء إلى ملفه. وفق [توثيق Angular لعزل التنسيقات](https://angular.dev/guide/components/styling)، CSS الخاص بالمكوّن الأب لا يصل تلقائيًا إلى DOM داخل الابن؛ استعمل خصائص CSS العامة المناسبة مثل `--preferences-gap`، أو ضع القاعدة عند مالك العنصر. `display: contents` مستخدم فقط لأجزاء البطاقة التي يلزمها الاحتفاظ بهندسة الفتحة الحالية؛ لا تعممه على المكونات التفاعلية.

عند نقل inline styles إلى SCSS حافظ على ترتيب القواعد وخصوصيتها؛ اختبر العرض المدمج قبل اعتبار النقل محايدًا.

## 6. الواجهات العامة والتحميل

صدّر ما يحتاجه المستهلك فقط. `AppearancePreferences` موجود في `shared/ui/public-api.ts`. نافذة الخيارات وfactory عرض الجدول تظل داخلية؛ صفحات الأعمال تستهلك `MyDataGrid` من الواجهة العامة. لا تصدّر محركات الرسوم والتقارير المؤجلة من barrel الإقلاع. تبقى الأجزاء الخاصة بالدول داخل مدخل الميزة الكسول.

احتفظ بـSignals و`computed` للقيم المشتقة؛ لا تنشئ effect ينسخ قيمة مشتقة إلى signal أخرى. تُقبل الآثار المرتبطة بالمزامنة والعمر القائمين مع الحفاظ على سلوكهما أثناء هذا refactor. لا تدّع تحسن زمن العرض لمجرد تقليل حجم الملفات؛ سجّل build والقياسات الفعلية عند ادعاء تحسن الأداء.

## 7. PrimeNG والتحقق

قبل تعديل control مشترك: افحص PrimeNG MCP للنسخة المثبتة، ثم `validate_usage` على الناتج النهائي. metadata لا تثبت سلوك Angular أو المتصفح. `ngModelOptions` تابع لتوجيه Angular `NgModel` وليس input خاصًا بـPrimeNG؛ أداة metadata قد تبلّغ عنه خطأ. سجّل النص الخام ثم تحقّق من خصائص PrimeNG بعد استبعاد هذا التوجيه من نسخة الفحص فقط، واحتفظ به في المصدر. Angular compiler واختبار المتصفح هما دليل الدمج.

الحد الأدنى لتغيير يماثل هذا النطاق:

1. فحص architecture والأنواع، بما فيه القوالب عبر Angular compiler.
2. اختبار التكامل الذي يمر عبر المكوّن العام إلى الجزء الداخلي؛ إعدادات العرض لا تغيّر source أو filters.
3. اختبارات حراسة المدخلات غير المدعومة والأعمدة المطلوبة/آخر عمود والـsnapshot والسياق.
4. build إنتاجي، ثم متصفح للجدول والـpaging والخيارات والإسقاط، وللبطاقات والنوافذ التي نُقلت.
5. حالات اللغة العربية والإنجليزية، RTL، المظهرين، والهاتف والمكتب للمساحات المتأثرة، حسب تقرير التنفيذ.
6. تحديث كتب الملاك و`required-files.json` ثم توليد الوثائق والتحقق منها.

الاختبارات تستخدم fixtures واعتراض الطلبات. لا يعني نجاحها قبول API المستضاف أو إغلاق بوابات الإنتاج أو إثبات تطابق بصري كامل مع عميل آخر.

## 8. ما نتجنبه

لا engine للنماذج أو الصفحات، ولا base CRUD class، ولا متجر عام لحالة كل الجداول، ولا نقل قرارات الدول إلى Shared، ولا API لجزء داخلي لمجرد وجود ملف منفصل. تبقى استراتيجية النماذج هي Angular Signal Forms مع الطبقة الخفيفة في [دليل النماذج](ANGULAR_SIGNAL_FORMS.md).
